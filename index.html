装得最多的那些，有多少在你这里根本装不上

上面那些榜回答的是「有多少人在装」。但下载量高不等于你装得上。

DSH 插件用它 package.json 里 peerDependencies 的 @deepseek-ai/dsh-tools 声明「我要配哪条 tools 版本线」，对不上就报 incompatible —— 而多数人会把那当成网络问题，然后反复重装。

「最高可装版本」是按它自己声明的范围，从已发布版本里挑出的最新一个 —— 装 <包名>@<这个版本> 而不是默认的 latest，才可能装上。 「无」表示已发布版本全都不在它自己声明的范围内。

为什么写通配符也不管用

本机跑的是 0.2.1-rc.2，是预发布版本。semver 的规则是： 预发布版本只被「同一个 major.minor.patch 且范围里也写了预发布」的范围接受。 所以写 * 不接受它，写 ^0.2.1 也不接受它， 只有 ^0.2.1-rc.1 这种形状才接受。这与 npm 自己的行为一致，但确实反直觉。

这组数字怎么来的

用 dsh-plugin-adoption v0.2.0 的版本线维度跑的。包名不是猜的 —— 只在 npm registry 元数据里的 repository 真的指回这个仓库时才采用，否则报 unknown， 而不是硬套一个别人的约束。判定分四档：blocked / ok / no-constraint / unknown，unknown 是独立的一种答案。

怎么读这份榜：下载量高说明有人在用，不说明好用； 它还会波动（同一插件不同月份能差几倍）。没有 npm 包的插件无法比较，不在这份榜里。
方法：插件清单与星数来自 dpharness.com 的公开 API，下载量来自 npm registry 官方 downloads 接口。样本是「两边都有数据」的那部分，不是随机抽样 —— 冷门插件更容易缺数据，所以这份榜偏向有 npm 包的插件。

怎么装

用 GitHub 直链在国内常会卡在 fetch failed —— 那是超时，不是命令写错。换个能直连的地址前缀就行：

dsh plugin --profile <你的profile> add https://ghproxy.net/https://github.com/OWNER/REPO/releases/download/vX.Y.Z/NAME-X.Y.Z.tgz

装完重启一次 dsh。想自己查别的插件排名，用 dsh-plugin-adoption。

尺子：查任意插件的真实下载量

榜单上的每个数字都来自 npm registry 官方接口。这把尺子用的是同一个接口 —— 所以你可以自己核对榜单里的任何一个数，也可以查榜单上没收录的插件。 数据实时取，不用等。

想知道榜单是怎么算出来的？

三条命令，你在本地跑一遍就知道：

npm view dsh-pet version curl -s https://api.npmjs.org/downloads/point/last-month/dsh-pet curl -s "https://api.deepseek1024.com/v1/plugins/search?q=dsh-pet"

第二条给出的是 npm 全网的月下载量（含 CI 和镜像，不是本站安装数）； 第三条给出的是站方收录的条目和它的星数。榜单里的「星排」和「下载排」 就是把同一批插件分别按这两个数排序，然后比名次差。

数据抓取于 2026-10-26，可复现。
